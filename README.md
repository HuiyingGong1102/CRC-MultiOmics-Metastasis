# CRC Metastasis Network Analysis

A reproducible R/Python demonstration of protein module clustering,
coarse-grained and fine-grained directed network decomposition, and GLMY
persistent path homology. The current demo uses **proteomics data**; this
repository does not yet demonstrate an integrated multi-omics analysis.
The supplied demo is intended to illustrate the computational workflow,
not to establish biological causality or reproduce unspecified manuscript results.

## Repository contents

```text
R/function.R                         All shared R functions in one file
scripts/01_read_data.R                Data preparation and linear fitting
scripts/02_clustering.py              Four-group linear AR(1) clustering

tools/README.md                      External GLMY executable requirements

```

## 2. Installation guide

Download or clone this repository and open a PowerShell terminal at its root.
Install R 4.5.1 and Python 3.12 using your normal installation method. Use an
existing compatible environment or create a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Rscript scripts/check_dependencies.R --install
```

`check_dependencies.R` installs missing packages from CRAN; it reports the
versions found and the tested versions. It does not downgrade existing packages.
The tested GPU PyTorch build was 2.7.1+cu128. `requirements.txt` pins the public
PyTorch version; CPU/CUDA wheel selection depends on the configured package
index. Verify the actual installation before comparing numerical results:

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
Rscript scripts/check_dependencies.R
```

For step 05, use the research group's bundled application at
`tools/GLMY.exe`. The executable is included for Windows users under the
MIT License. Steps 01-04 do not require it. No separate GLMY installation
is needed.

Installation time on a normal desktop is estimated at **10-30 minutes**, mostly
for Python/PyTorch downloads; this is an estimate, not a measured clean install.
Network speed and cached packages can substantially change it.

## 4. Methods and reproducibility

### Data preparation and clustering

Step 01 applies `2^data + 1`, sorts samples within each group by ascending total
abundance, and applies log2 to abundance and total. Linear fitting uses
`equation_fit(thread=8)`. Output columns retain sample identifiers and group
order. Dimensions, values and CSV round trips are checked.

Step 02 clusters proteins, with 167 sample measurements as features. It fits
four group-specific linear means and AR(1) covariance blocks. k=2 through 10
is run ten times per k; each run uses KMeans with n_init=10. The base seed is
20261004 and the run seed is `base_seed + 100*k + run`. Python, NumPy, PyTorch
and KMeans seeds are set; deterministic PyTorch algorithms are enabled.
The optimizer retains AdamW, learning rate 1e-5, 25 updates per outer iteration,
relative stopping tolerance 1e-4 and a 10000-iteration limit. The earlier demo
met that original stopping criterion in 1-2 outer iterations; this criterion
does not certify a global optimum. Final posteriors are recomputed after the
last update and checked for normalization.

BIC uses the observed mixture negative log likelihood:
`BIC = 2*NLL + log(number_of_proteins)*(8 + 8*k + k - 1)`.
The legacy `log-likelihood` JSON field stores the original Q objective rather
than the observed likelihood; use `negative_log_likelihood` and `BIC` for model
comparison. `legacy_Q_BIC` is retained for traceability. JSON labels are zero
based; labels.csv and figure module names are one based.

Step 03 takes the minimum BIC over ten runs for each k, then selects the lowest
across k. Faint points are per-protein linear fitted values, and colored lines
are fits of the module mean. `get_power_par` uses OLS with an NNLS fallback
when fitted values are negative. The index is log2 total sample abundance,
not chronological time. PNG is 200 dpi and TIFF is 300 dpi.

### Network analysis

Step 04 recovers positive abundance with `2^data_all`. Coarse nodes are module
means on that scale; fine nodes are individual proteins within each module.
Each network is independently sorted by its total abundance and log2 transformed.
Relationships are selected with the original adaptive elastic-net
`get_interaction` using 1000 points on fitted linear curves. These points are
modeled interpolation points, not additional independent measurements.
Per-target seeds are deterministic. Zero-order decomposition uses 100-point
curves, Nelder-Mead (50000 iterations maximum) and the original negative-curve
penalty. The cached linear integral is equivalent to the original zero-order
`get_effect`, verified numerically. Isolated nodes are handled explicitly.

Each `<group>_links.csv` has exactly these columns:

| Column | Meaning |
| --- | --- |
| From | Incoming source node |
| To | Response/target node |
| size | Mean target self effect raised to 0.1, multiplied by 30 |
| Effect | Mean signed incoming decomposition effect |
| edge_type | 1 for Effect > 0, otherwise 2 |
| weight | abs(Effect) raised to 0.1, multiplied by 2 |

CSV files have no row names or quoting. Link endpoints and numerical values
are checked. Curves show black observations, blue total, red self and green
incoming effects. The inferred edges describe this fitted model and should
not be interpreted as experimentally established causal interactions.

### GLMY homology

Step 05 uses directed edges with **signed Effect**, not the visualization
weight. All networks use a common additive shift of at least 100, increased
automatically to keep every GLMY input weight positive. The tested shift was
14536.0444831686. Each executable process has an isolated temporary working
directory, and isolated vertices are included from the clustering model.
GLMY is requested to compute through the supplied dimension setting 4;
barcodes display H0-H3. Finite thresholds are shifted back, infinite deaths
remain infinite, and zero-length intervals remain explicitly visible.
Initial vertex classes are born before the displayed edge range and shown
with left arrows; right arrows represent infinite intervals. Raw JSON
preserves the entire filtration. The timeout is 120 seconds per network;
failures are recorded and never substituted with empty homology results.

## 5. Use with your own data

1. Provide a finite, preprocessed log2 abundance matrix with unique feature
   row names and sample column names. Missing-value imputation and quality
   control must be completed before this workflow; they are not implemented.
2. Provide metadata with unique `Sample` identifiers and `Group` labels that
   match the matrix. Use compatible files at the documented demo paths or edit
   input paths in step 01. Keep an untouched copy of the bundled demo.
3. For different group names, change the four-group lists consistently in
   steps 01-05. The current clustering model explicitly assumes four groups.
4. The demo checks enforce its 90-run k grid and minimum sample counts. For
   different k ranges, run counts or grouping, update the matching validations
   as well as the configuration. Every selected group needs at least two samples.
5. Re-run all steps after changing input data or clustering parameters.
   Network and GLMY steps reselect the minimum-BIC clustering result.

The protein labels are feature identifiers; other abundance-based assays may
be adaptable, but their transformations and biological assumptions must be
validated independently. The current evidence is limited to the proteomics demo.
